# 수학 퀴즈배틀 (5학년 2학기 1단원)

반 전체가 크롬북으로 동시에 접속해 같은 문제를 풀고, 점수로 팀을 나눠 1대1 게임을 합니다.

- **학생** 각자 크롬북 — 문제 풀이, 팀 대결
- **전자칠판** 읽기 전용 — QR·대기 인원·타이머·팀 발표·팀 승수
- **교사 컴퓨터** 제어 — 시작/정지, 현황, 팀 수동 조정

---

## 처음 한 번만 (두 가지)

### 1) 프로그램 설치

명령 프롬프트에서 이 폴더로 간 뒤:

```bash
npm install
```

### 2) Firebase 규칙 넣기

Firebase 콘솔 → **Realtime Database → 규칙** 탭에서,
이 폴더의 `firebase.rules.json` 안에 있는 `rules` 부분을 붙여넣고 **게시**를 누르세요.
(맨 위 `_설명` 항목은 빼고 붙여넣으세요.)

이걸 안 하면 학생이 접속해도 아무것도 저장되지 않습니다.

> 접속 설정값은 이미 `.env.local` 에 들어 있습니다. 이 파일은 GitHub에 올라가지 않습니다.

---

## 수업하는 법

### 1. 서버 켜기

```bash
npm run dev -- --host
```

주소가 두 개 뜹니다.
- 선생님 컴퓨터에서 쓸 주소: `http://localhost:5173`
- **학생 크롬북에서 쓸 주소**: `http://192.168.x.x:5173` 같은 두 번째 주소 (같은 와이파이여야 합니다)

### 2. 세션 만들기 (교사 컴퓨터)

`http://localhost:5173` → **선생님** → 단원·게임·시간·명단을 정하고 **세션 만들기**

명단은 한 줄에 한 명씩 씁니다. 한 번 넣으면 이 컴퓨터에 저장되어 다음 수업에도 그대로 씁니다.

### 3. 전자칠판 띄우기

교사 콘솔 오른쪽 위 **전자칠판 화면 열기** → 새 창이 열립니다. 이 창을 전자칠판으로 옮기고 전체화면(F11)으로 두세요.

칠판에 **QR과 6자리 코드**가 뜹니다. 학생은 둘 중 아무거나 쓰면 됩니다.

> 이 화면에는 **개인 점수나 등수가 절대 나오지 않습니다.** 팀 단위만 나옵니다.

### 4. 학생 접속

크롬북 카메라로 QR을 찍거나, 주소창에 학생용 주소를 넣고 6자리 코드를 칩니다.
이름을 고르면 끝입니다. 로그인·비밀번호 없습니다.

한 번 이름을 고르면 그 크롬북이 기억합니다. 새로고침하거나 화면을 덮었다 열어도 자기 자리로 돌아옵니다.

### 5. 진행

교사 콘솔의 **다음 단계로** 버튼을 순서대로 누릅니다.

```
대기실 → 문제 풀이 → 채점 → 팀 발표 → 팀 대결 → 결과
```

- 시간이 다 되면 자동으로 채점으로 넘어갑니다. 안 눌러도 됩니다.
- **일시정지**, **타이머 +2분** 은 문제 풀이 중에만 눌립니다.
- 자동 진행이 멈추면 드롭다운으로 어느 단계든 강제로 갈 수 있습니다.
- 크롬북이 멈춘 학생이 있으면 접속 현황에서 **자리 비우기**를 누르세요. 다른 크롬북에서 그 이름을 다시 고를 수 있습니다.

### 6. 끝나고

결과 화면에서 **오답 기록 저장하기**를 누르면 학생이 나중에 `#/review` 에서 자기 오답을 볼 수 있습니다.
저장되는 것은 이름·점수·답안뿐입니다. 학번이나 생년월일은 저장하지 않습니다.

## 게임 규칙 (번호 뽑기 대전)

통을 흔들어 번호 공을 뽑습니다.

- 숫자 공 1~12 각 한 장 + **꽝 2장**
- 시작할 때 각자 **히든 공 1장**을 비공개로 받습니다. 히든에는 꽝이 없습니다
- **첫 턴에는 꽝이 없습니다.** 꽝 2장은 1턴이 끝난 뒤에 통에 들어갑니다
- 매 턴 **뽑기 / 스탑**을 고릅니다. 스탑은 그 판에서 되돌릴 수 없습니다
- **꽝을 뽑으면 그 자리에서 집니다**
- 둘 다 스탑하면 히든을 공개해 합계가 큰 쪽이 이깁니다
- 한 턴에 **10초**까지 생각할 수 있습니다. 시간이 지나면 **자동으로 스탑**됩니다 (자동으로 뽑지 않습니다)
- 3판을 하고, **매 판 상대가 바뀝니다**
- 인원이 홀수면 남는 한 명이 **응원단장**이 됩니다. 판마다 돌아가며 맡습니다

## 확인용 명령

| 명령 | 하는 일 |
|---|---|
| `npm run check` | 문제 생성기 자동 검사 (템플릿당 1000회) |
| `npm run check:game` | 게임 규칙·팀 배분·매칭 검사 (판 4000회 시뮬레이션) |
| `npm run dump` | 검수용 100문항 → `out/dump.html` (인쇄하면 학습지) |
| `npm run snapshot:save` | 지금 문항을 합격 기준으로 저장 |
| `npm run snapshot:check` | 코드를 고친 뒤 문항이 달라졌는지 확인 |
| `npm run build` | 배포용으로 묶기 → `dist/` |

`#/stage` 주소는 게임 그림을 확인하는 개발용 화면입니다. 수업에는 쓰지 않습니다.

## 화면 주소

| 주소 | 화면 |
|---|---|
| `#/` | 첫 화면 |
| `#/teacher` | 세션 만들기 |
| `#/teacher/s/…` | 교사 콘솔 |
| `#/board/코드` | 전자칠판 (읽기 전용) |
| `#/play/코드` | 학생 |
| `#/review` | 오답 조회 |
| `#/practice` | 혼자 연습 (인터넷 없이) |

주소에 `#` 이 붙는 이유: GitHub Pages는 `/play/ABC123` 같은 주소를 새로고침하면 404가 납니다. 해시를 쓰면 리포 이름이 무엇이든 그대로 돕니다.

## 폴더 구조

```
src/
  units/            단원별 문제 생성기 — Firebase 를 모른다
    _types.ts       Problem, Visual 판별 유니온, 단원 모듈 계약
    _guards.ts      가드 G1~G8, 어림 계산(두 방법으로 검산)
    5-2-1/          t1.ts ~ t7.ts + index.ts
  games/            게임 모듈
    _types.ts       계약: 입력은 팀 배정, 출력은 팀별 점수
    draw-duel/      번호 뽑기 대전 (engine / stage / 화면)
  session/          세션 타입·Firebase 접근·채점·팀 배분
  screens/          teacher / board / student / review
  components/       수직선·표 렌더러, QR
  lib/              난수, localStorage, firebase 초기화
scripts/            검사·덤프·스냅샷 도구
docs/               설계 문서 (근거는 전부 여기)
```

새 단원 = `src/units/` 에 파일 하나 + `src/units/index.ts` 에 한 줄.
새 게임 = `src/games/` 에 폴더 하나 + `src/games/index.ts` 에 한 줄.

**그 외 파일을 고쳐야 한다면 인터페이스가 잘못된 것이니 멈추고 알려주세요.**
