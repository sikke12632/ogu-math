# 인수인계 — 2단원 상 난이도 숫자 조정

## 할 일

2단원(5-2 분수의 곱셈) **상 난이도 문항의 숫자가 너무 쉽다.**
유형은 대체로 괜찮다. 숫자가 문제다 — `1/2 × 12`, `16 m 의 1/4`, 분모 2·3·4 같은 것들이
암산으로 끝나서 상 문항이 상 답지 않다. **고난도는 고난도답게 나와야 한다.**

선생님 기준은 숫자를 보고 판단하는 것이다. 유형 설명이나 주석 말고 **실제로 뽑힌 문항**으로 확인할 것.

숫자는 거의 다 각 생성 함수 안의 `rng.pick([...])` / `rng.int(a, b)` 와 그 아래 가드(`return null`)에서 정해진다.

## 확인 방법

```bash
npm run dump -- 5-2-2 3 2    # 상 난이도, 유형별 2개 → out/dump-5-2-2-난이도3.html
npm run check:2              # 2단원 검수기 (정답 재계산·표기·생성 성공률)
npx tsc --noEmit
```

`check:2` 는 가드가 너무 빡빡하면 "600번 중 N번만 만들어졌습니다" 로 실패한다. 숫자를 어렵게 조이면 이게 먼저 걸린다.

## 지켜야 할 것

- **시중 문항 복제 금지.** 수치만 바꾸는 것도 복제다. 유형(얼개)만 가져온다
- **분수 답은 선택형.** 크롬북에서 `4와 2/7` 을 칠 수 없다. 단답형은 자연수 답만
- 분수 표기는 `[3/4]`, `[1_2/3]`. 가분수를 문제에 내놓지 않는다(검수기가 막는다). 분모 48 초과 금지
- 오답 보기는 아이들이 실제로 하는 실수에서 뽑는다 (분모에도 곱함, 자연수만 곱함 등)
- 조사는 숫자를 읽는 소리로 정한다 — `josa`/`josaAfter` 를 쓸 것 ("3분의 2**를**")
- 답이 하나여야 한다. 모양이나 크기만 보고 찍히면 안 된다
- 5학년 2학기 범위: 분수의 곱셈까지. **분수의 나눗셈은 6학년** (T12 가 그래서 선택형이다)
- 배포는 선생님이 말할 때만. 수업 중에는 절대 푸시하지 않는다

## 2026-09-18 조정 — 숫자를 조였다

위 "약한 곳" 여섯 중 다섯을 손봤다. 공통 원칙은 **상에서 분모 2 와 분자 1 을 뽑지 않는다**이다.
`[1/2]`·`[1/4]` 가 들어가면 어떤 얼개든 암산으로 끝났다.

| 유형 | 전 | 후 |
|---|---|---|
| T7 | `[1/2] × [1/2] × [1/3]` | 분모 3~9·분자 2 이상, 답 분모 8 이상, 같은 분수 반복 금지 |
| T8 | `1 km의 [1/2]` / 오답 `72cm` | 분자 2 이상. 오답은 세 가지 실수(한 묶음만·남은 쪽·묶음 하나 더/덜)에서만 |
| T9 | `[1/4] × 6 = [1/4]` (분모에도 곱함) | 틀린 것은 분자와 자연수를 약분하는 실수·분자끼리 약분하는 실수로. **맞는 보기 셋도 같은 수 범위**(분모 5~9·분자 2 이상)로 — 셋이 쉬우면 남은 하나를 찍는다 |
| T11 | `[1_1/2] × [1/2] ÷ 2` | 두 변 다 대분수, 분모 3~8, 서로 다른 분모 |
| T12 | `[1/4] 곱해 [1/2]` | 곱수 분모 4~9·분자 2 이상. 오답에서 "문제에 적힌 수" 둘을 뺐다 — 2지선다가 되고 있었다 |
| T13 | `[1/2] 쓰고 남은 것의 [1/2]` | 분모 3~8, 둘 다 단위분수 금지, 답 분모 48 까지 허용. 오답은 실수 네 가지에서만 뽑고 셋이 안 모이면 버림 — 첫 오답 식이 틀려 있어(정답과 같은 값) 흔든 값 `[13/37]` 이 채워지고 있었다 |
| T14 | `[4/24]` | 분모 24~48, 약분 결과가 단위분수면 버림, 답 7 이상 |
| T16 | `[1/2] 의 [1/2] 이 5명` | 분자 2 이상·분모 3~9, 겹친 비율 분모 8~48 |
| T17 | `[1/2] × 4 < □ < [1/2] × 21` | 분모 3~8·분자 2 이상, 양 끝이 다 자연수면 버림, 답 2~8개 |
| T18 | `[1/4]`, 16 m → 1 m | 분자 2 이상·분모 3~8, 높이 20~100 m, 답 4 m 이상 |
| T19 | 절반이 `[1_1/2]시간` | 분모 3~8, 두 대의 시간이 같으면 버림 |

T10·T15 는 손대지 않았다. 이미 넷을 다 계산해야 풀린다.

**생성률이 먼저 걸린다.** 기약이 아니면 `return null` 하는 방식으로는 분모 4·6·8 에서
절반이 날아가 T13·T17·T19 가 검수 기준(600번 중 120번) 아래로 떨어졌다.
그래서 그 셋은 기약이 나올 때까지 **다시 뽑는다** (`reducedFrac`, `while (gcd…)`).
숫자를 더 조일 때도 같은 방법을 쓸 것.
