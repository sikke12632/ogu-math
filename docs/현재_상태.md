## 교실에서 나온 것 (실제 피드백)

**해결됨**
- 학생이 못 들어감 → 읽기 전에 익명 로그인을 안 해서 규칙에 막혔던 것. 고침
- QR 찍으면 빈 화면 → 주소의 `#` 을 크롬북 QR 앱이 못 열었음. `?c=코드` 로 바꿈
- 다음 판으로 안 넘어감 → 배경 탭에서 setTimeout 이 늘어짐. 시각 기록 방식으로 바꿈 (2.5초)
- 게임 화면 글씨 작고 복잡함 → 통 왼쪽 / 점수 오른쪽 2단, 글씨 2배로

**미해결 — 다음에 할 일**
1. **학생마다 차단 여부가 다르다.** 되는 학생과 안 되는 학생이 섞여 있음.
   `#/check` 진단 화면을 만들어 뒀으니, 차단된 크롬북에서 열어 어디서 ✗ 가 뜨는지 확인해야 함.
   - 화면조차 안 열림 → `github.io` 자체가 막힘
   - Firebase 로그인 ✗ → `identitytoolkit.googleapis.com` 막힘
   - 데이터 읽기 ✗ → `firebasedatabase.app` 막힘
   결과에 따라 정보부에 허용 요청하거나, 로컬 서버(`npm.cmd run dev -- --host`)로 우회.
   **단 로컬 서버로도 Firebase 는 인터넷을 거치므로, Firebase 가 막혔으면 우회가 안 된다.**

## 확인 안 된 것 (정직하게)

- **25명 동시 접속은 안 해봤다.** 최대 3명으로만 테스트. 규칙·팀배분·매칭은 컴퓨터로 4000판 검증했지만 네트워크 부하는 미검증
- **응원 보내기** — 받는 화면만 확인. 보내는 쪽이 대전 중인 학생 화면에 실제로 뜨는지는 미확인
- **MVP 지목** — 기능은 동작하나 테스트에서 아무도 안 눌러 "없음" 으로만 나옴
- **골든 스냅샷 미저장** — `npm.cmd run snapshot:save` 를 아직 안 함
- **번들 657KB (압축 177KB)** — 대부분 Firebase. 학교 와이파이가 느리면 첫 접속이 느릴 수 있음

## 설계 원칙 (어기면 안 되는 것)

`CLAUDE_1.md` 와 `docs/` 가 정본이다. 특히:

- **전자칠판에 개인 점수·등수를 절대 띄우지 않는다.** 팀 단위만
- **게임 화면에 "아직 안 나온 숫자" 목록을 그리지 않는다.** 카운팅이 실력이 되어야 한다
- **phase 는 교사 클라이언트만 바꾼다.** 학생·보드는 읽기만
- **교사 화면과 오답 기록은 실명, 칠판과 친구 화면은 별명**
- 게임 규칙·수치는 확정. 바꾸지 말 것 (숫자 1~12 + 꽝 2장, 히든 1장, 첫 턴 안전, 10초 자동 스탑)
- 단원·게임 추가가 코어 코드 수정을 요구하면 **멈추고 보고**
