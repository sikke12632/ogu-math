## 교실에서 나온 것 (실제 피드백)

**해결됨**
- 학생이 못 들어감 → 읽기 전에 익명 로그인을 안 해서 규칙에 막혔던 것. 고침
- QR 찍으면 빈 화면 → 주소의 `#` 을 크롬북 QR 앱이 못 열었음. `?c=코드` 로 바꿈
- 다음 판으로 안 넘어감 → 배경 탭에서 setTimeout 이 늘어짐. 시각 기록 방식으로 바꿈 (2.5초)
- 게임 화면 글씨 작고 복잡함 → 통 왼쪽 / 점수 오른쪽 2단, 글씨 2배로

**응원 보내기 → 배팅으로 바뀜** (2026-08-25)

응원단장이 하는 일이 "응원 버튼 누르기" 에서 **"팀원 한 명에게 걸기"** 로 바뀌었다.

- 고른 친구가 이기면 그 판이 **팀 점수 2점**. 지거나 비기면 평소대로 (손해 없음)
- **한 번 고르면 못 바꾼다**
- **승부가 이미 끝난 친구에게는 걸 수 없다.** 이 화면에는 팀원들 승패가 실시간으로 뜨기 때문에,
  안 막으면 이긴 걸 보고 나서 거는 사후 확정이 된다
- 걸린 친구 화면에는 **누가 걸었는지는 빼고** "누가 너한테 걸었어!" 만 뜬다.
  이름을 띄우면 졌을 때 누구 것을 날렸는지 서로 알게 된다
- 점수 표시가 **"3승" 에서 "3점" 으로** 바뀌었다. 배팅이 맞으면 한 판이 2점이라 승수와 다르다

같이 고친 것

- **유령 응원 버그** — 옛 응원 기록이 안 지워져서, 지난 판에 받은 응원이 다음 판 시작하자마자
  다시 뜨던 문제. 배팅은 판 번호별로 저장해 구조적으로 막았다
- **MVP 문구** — 화면엔 "이번 판 MVP" 라고 쓰여 있었지만 데이터는 판 구분 없이 한 통에 모인다.
  문구를 "오늘 우리 팀 MVP" 로 바꿔 실제와 맞췄다

**차단 원인 확인 — 웹키퍼** (2026-08-25)

학생 디벗에서 빈 화면이 뜨는 원인은 **웹키퍼(학교 필터)** 였다.
막히는 단계는 기기마다 다르지만 **대체로 Firebase 쪽**이다.

**지금 당장 쓸 수 있는 것이 하나 있다 — `#/practice` (혼자 풀기).**
이 화면은 Firebase 를 전혀 쓰지 않는다. 문제를 기기 안에서 직접 만들어 낸다.
디벗이 `github.io` 만 열리면 차단과 상관없이 바로 쓸 수 있다.
혼자 풀고 채점받고 오답 확인까지 된다. 팀·게임·교사 화면만 안 된다.

**여기까지 알아낸 것** (2026-08-25)

| 확인한 것 | 결과 |
|---|---|
| 메인 화면 · 혼자 풀기(`#/practice`) | **된다** |
| 코드 치고 들어가기 · 기록 보기(`#/review`) | 하얗게 되며 웹키퍼 차단 |
| `#/check` | **끝까지 다 초록불이 들어온 뒤** 하얘짐 |
| 주소를 하나씩 눌러 보기 | **전부 열린다** |
| 실시간 연결(WebSocket) 30초 붙잡기 | **버틴다** |
| 지난 수업 | **12명은 통과해서 게임까지 진행함** |

읽는 법은 이렇다.

- **완전 차단이 아니다.** 12명이 통과했고, 주소도 하나씩은 다 열린다
- 웹키퍼 확장은 **방문 기록을 읽어 서버에 판정을 물어본다.** 그래서 반응이 몇 초 늦고,
  판정이 오는 타이밍이 기기마다 다르다. "되는 애/안 되는 애" 와 "되던 게 안 되는 것" 이 이걸로 설명된다
- 로그인하는 화면만 죽고 안 하는 화면은 산다 → **Firebase 로그인 경로가 걸린다**

**고친 것 — 접속하는 주소를 둘 줄였다**

Firebase 로그인은 익명 로그인만 써도 뒤에서 두 곳을 더 불러왔다.
`apis.google.com` 의 스크립트와 `firebaseapp.com` 의 숨은 프레임이다.
**팝업 로그인용이라 우리는 안 쓰는데도 딸려 왔고, 로그인이 끝난 뒤에 뒤늦게 불러온다.**
"다 되는 것처럼 보이다가 몇 초 뒤에 하얘지는" 증상과 타이밍이 맞는다.

`src/lib/firebase.ts` 에서 `getAuth()` 대신 `initializeAuth()` 를 쓰도록 바꿔 껐다.
접속하는 외부 주소가 **다섯에서 셋으로** 줄었다.

> **주의.** 나중에 팝업·리다이렉트 로그인(구글 계정 로그인 등)을 쓰게 되면
> 이걸 되살려야 한다. 지금은 익명 로그인만 쓰므로 아무 문제 없다.

**허용 요청할 때 반드시 짚을 것**

실시간 연결이 실제로 붙는 주소는 설정에 적은 것과 **다르다.**

```
설정값     math-game-e3402-default-rtdb.asia-southeast1.firebasedatabase.app
실제 연결   s-gke-apse1-nssi4-0.asia-southeast1.firebasedatabase.app
```

**설정값 하나만 허용받으면 여전히 막힌다.** `*.firebasedatabase.app` 로 요청해야 한다.

**Firestore 로 옮겼다** (2026-08-25)

결정적인 단서는 이것이었다 — **선생님이 만든 다른 Firestore 사이트는 같은 디벗에서 잘 돈다.**
그러면 범인은 Realtime Database 주소(`*.firebasedatabase.app`)다.
생소한 도메인이라 필터가 "미분류" 로 잡아 막는다.
`firestore.googleapis.com` 은 구글 주소라 사실상 못 막는다 — 막으면 클래스룸도 같이 죽는다.

**화면 코드는 한 줄도 안 고쳤다.** `api.ts` 의 함수 이름과 인자를 그대로 두고 속만 바꿨다.
흩어진 문서를 예전과 똑같은 모양의 `Session` 하나로 합쳐서 넘긴다.

옮기면서 달라진 것 넷.

1. **문서를 쪼갰다.** Firestore 는 한 문서에 초당 한 번쯤만 쓸 수 있다.
   25명이 한 덩어리에 쓰면 한계에 걸린다. "누가 쓰는가" 로 나눴다
2. **"나 여기 있어요" 신호를 대전 중에만 촘촘히 보낸다** (4초 / 그 밖에는 20초).
   계속 4초마다 쓰면 **한 시간 수업 한 번에 하루치 무료 한도를 다 쓴다**
3. **튕김 처리가 10초에서 약 20초로 늘었다.** Realtime Database 에 있던
   "끊기면 서버가 알아서 표시" 기능이 Firestore 에는 없어서, 마지막 신호로 판단한다.
   줄이려면 `STALE_MS_GAME` 과 DrawDuel 의 10초 유예를 같이 손봐야 한다
4. **번들을 화면별로 쪼갰다.** Firestore SDK 가 커서 그냥 두면 첫 로딩이
   183KB → 280KB 로 늘어난다. Firebase 쓰는 화면만 나중에 받게 했더니
   메인·혼자 풀기 첫 로딩이 **76KB** 로 오히려 전보다 빨라졌다

**콘솔 설정은 끝났다** (Firestore 생성 + 규칙 게시). `docs/Firestore_설정.md` 참고.
지난 오답 기록은 시험용이라 옮기지 않았다.

**되돌리려면** `git checkout 리얼타임DB-마지막-작동본`.
Realtime Database 는 아직 안 지웠으니 그대로 돌아간다.

**기기 두 대로 확인한 것** (로컬)
세션 만들기 → 이름 잡기 → 접속 현황 실시간 반영 → 문제 풀이 → 답안 저장 →
제출 → 채점(문항별 정답률) → 팀 발표 → 팀 대결 진입까지 전부 정상.
**아직 못 해 본 것: 실제 대전 두 명이 붙는 것, 25명 동시 접속.**

**Firestore 한도가 수업 중에 터졌다** (2026-08-25)

두 번째 세션에서 학생들이 이름을 눌러도 아무 반응이 없었다.
원인은 `[resource-exhausted] Quota exceeded` — **하루 쓰기 한도(2만 건)를 다 쓴 것.**
읽기는 되고 쓰기만 막혀 있었다.

**왜 터졌나.** 접속 신호("나 있어요")를 대전 중 4초마다 보냈다.
25명이면 한 시간에 2만 번이다. 수업 한 번이 하루치를 다 쓴다.
읽기는 더 나빴다. 신호를 **학생 25명까지 전부 듣고 있어서**
신호 한 번이 읽기 27번이 됐다. 계산해 보면 한 시간에 60만 회다.
쓰기가 먼저 걸렸을 뿐, 읽기가 터지는 게 정상이었다.

**세 가지를 고쳤다.**

1. **접속 신호를 명단에서 떼어냈다** (`presence` 묶음).
   **듣는 것은 교사 화면과 칠판뿐이다.** 학생은 친구가 붙어 있는지 알 필요가 없다.
   `useSession(id, { withPresence: true })` 를 켠 화면만 받는다
2. **대전 중 신호를 없앴다.** 상대가 튕겼는지는 신호로 알 필요가 없다 —
   **그 판에 아무것도 안 고르는 것**이 곧 없다는 뜻이다.
   자리에 있으면 10초 뒤 자기 기기가 저절로 스탑을 쓴다.
   제한시간 10초 + 여유 12초가 지나도 조용하면 그때 패배 처리한다
3. **신호 간격 45초, 화면을 안 볼 때는 아예 안 보낸다.** 답안 저장도 1.5초로 묶었다

| | 예전 | 지금 |
|---|---|---|
| 쓰기 (1시간) | 약 9,000 | 약 2,800 |
| 읽기 (1시간) | 60만 이상 | 약 7,000 |

하루 한도 안에서 **7교시까지 돌릴 수 있다.**

**그리고 더 중요한 것 — 화면이 이제 사실대로 말한다.**
`claimSeat` 과 `setNickname` 이 실패해도 아무 말이 없어서, 학생은 버튼이
고장 난 줄 알았고 원인을 찾는 데 한참 걸렸다.
`.catch` 를 붙이고 한도 초과를 사람 말로 바꿔 띄운다.
**앞으로 이런 일이 생기면 화면이 먼저 알려 준다.**

> 한도가 또 모자라면 Firebase 콘솔에서 **Blaze(종량제)** 로 올리면 된다.
> 무료 한도는 그대로 유지되고 초과분만 과금되는데, 이 규모는 하루 몇십 원이다.

**다음에 할 일**
0. **실제 수업에서 확인한다.** 한도가 다시 터지지 않는지, 대전 중 튕김 처리가
   제대로 되는지 본다. 튕김은 이제 **약 22초** 뒤에 패배 처리된다
1. **차단된 디벗에서 `docs/진단_눌러서확인.html` 을 연다.**
   자동 확인은 못 쓴다 — 확인하다가 확인 화면이 같이 죽는다.
   이 파일은 새 탭으로 열어 보게 하고 사람이 본 것을 눌러 기록한다.
   진단 화면을 다시 만들어서, 이제 **첫 실패에서 멈추지 않고 도메인을 하나씩 따로**
   두드린다. 끝나면 화면 아래에 정보부로 그대로 보낼 글이 나오고 복사 버튼이 있다.
   **기기 두세 대에서 해 볼 것.** 한 대만 보고 요청하면 허용받은 뒤 또 막힌다.
2. **정보부에 허용 요청.** `docs/웹키퍼_허용요청.md` 에 그대로 보낼 글을 써 뒀다.
   허용이 필요한 주소는 넷이고, 데이터 주소는 **WebSocket(wss) 도 함께** 열려야 한다.
3. **교사 노트북 우회가 가능한지 2분 확인.**
   `npm.cmd run dev -- --host` → 뜨는 `Network:` 주소를 디벗 크롬에 입력.
   열리면 노트북 서버 방식이 가능성 있고, 안 열리면 학교 와이파이가 기기끼리
   못 보게 막아 둔 것이라(단말 격리) 웹키퍼 허용 외에 길이 없다.
   **주의: 노트북으로 화면을 띄워도 Firebase 는 인터넷을 거친다.**
   세션·게임까지 되게 하려면 Firebase 를 대신할 서버를 노트북에서 돌려야 하고,
   그건 코드를 꽤 고쳐야 하는 일이다. 3번 확인 결과를 보고 결정할 것.

## 확인 안 된 것 (정직하게)

- **25명 동시 접속은 안 해봤다.** 최대 3명으로만 테스트. 규칙·팀배분·매칭은 컴퓨터로 4000판 검증했지만 네트워크 부하는 미검증
- **배팅** — 점수 계산과 잠금 규칙은 `npm.cmd run check:game` 으로 검증했다.
  하지만 **기기 두 대로 실제로 걸어 보지는 않았다.** 홀수 인원이어야 응원단장이 생기므로
  테스트하려면 학생 3명(또는 5명)으로 세션을 열어야 한다
- **MVP 지목** — 기능은 동작하나 테스트에서 아무도 안 눌러 "없음" 으로만 나옴
- **번들 657KB (압축 177KB)** — 대부분 Firebase. 학교 와이파이가 느리면 첫 접속이 느릴 수 있음

```bash
npm.cmd run build        # 빌드
```

다섯 다 통과해야 push 한다.

## 설계 원칙 (어기면 안 되는 것)

`CLAUDE_1.md` 와 `docs/` 가 정본이다. 특히:

- **전자칠판에 개인 점수·등수를 절대 띄우지 않는다.** 팀 단위만
- **게임 화면에 "아직 안 나온 숫자" 목록을 그리지 않는다.** 카운팅이 실력이 되어야 한다
- **통 안에 있는 공에는 숫자도 색도 값을 드러내지 않는다.**
  드러내면 통에 없는 숫자를 골라내서 **상대의 숨은 공을 정확히 맞힐 수 있다.**
  1~12 중 내 숨은 공·내가 뽑은 공·상대가 뽑은 공을 빼면 통에 있어야 할 숫자가 나오는데,
  거기서 하나가 비기 때문이다. 색만 남겨도 뚫린다 — 색이 값에서 나오기 때문이다.
  꽝만 빨갛게 둔다. 몇 개인지는 어차피 화면에 적혀 있고, 꽝이 통에 들어가는 순간이
  눈에 보여야 규칙이 와닿는다
- **phase 는 교사 클라이언트만 바꾼다.** 학생·보드는 읽기만
- **교사 화면과 오답 기록은 실명, 칠판과 친구 화면은 별명**
- 게임 규칙·수치는 확정. 바꾸지 말 것 (숫자 1~12 + 꽝 2장, 히든 1장, 첫 턴 안전, 10초 자동 스탑)
- **배팅은 손해가 없다.** 걸었다 져도 감점하지 않는다. 감점을 넣으면
  지목당한 아이가 원망을 듣게 되고, "하위권을 죽이지 않는다" 는 원칙이 깨진다
- 단원·게임 추가가 코어 코드 수정을 요구하면 **멈추고 보고**
