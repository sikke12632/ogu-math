# 웹키퍼 허용 요청 — 정보부에 보낼 내용

학생 디벗에서 수업용 웹앱이 **웹키퍼에 차단되어** 빈 화면이 뜬다.
막히는 지점은 기기마다 다르지만 **대부분 Firebase 쪽**이다.

이 문서는 정보부(또는 웹키퍼 관리자)에 그대로 보낼 수 있게 쓴 것이다.
아래 "보낼 내용" 부분만 복사해서 보내면 된다.

---

## 0. 먼저 — 기기 차단인가, 네트워크 차단인가

**이걸 모르고 정보부에 보내면 엉뚱한 담당자에게 가서 시간만 버린다.**

웹키퍼는 구글 제품이 아니다(플랜티넷 제품). 다만 디벗 같은 관리 크롬북에서는
**구글 관리콘솔을 통해 기기에 얹히는 경우가 많다.** 그래서 두 가지로 갈린다.

| 방식 | 어디서 푸나 |
|---|---|
| **기기 쪽** — Chrome 정책 / 강제 설치 확장 | 구글 관리콘솔 (교사 권한으로 될 수도 있음) |
| **네트워크 쪽** — 학교 인터넷 관문에서 차단 | 웹키퍼 관리자 포털 (정보부·교육청만 가능) |

### 확인 1 — 휴대폰 핫스팟 (2분, 제일 확실함)

차단된 디벗을 **선생님 휴대폰 핫스팟**에 연결하고 `#/check` 를 다시 연다.

- **되면** → 학교 네트워크가 막는 것. 정보부·교육청 네트워크 담당이 풀어야 한다
- **안 되면** → 기기에 붙은 정책·확장. 관리콘솔에서 손댈 여지가 있다

### 확인 2 — `chrome://policy` (30초)

차단된 디벗 주소창에 `chrome://policy` 를 그대로 친다. 볼 것 두 가지.

- `URLBlocklist` — 차단 목록이 있으면 기기 쪽 정책이다. 내용이 그대로 보인다
- `ExtensionInstallForcelist` — 강제로 깔린 확장 목록. 웹키퍼가 여기 있으면 확장 방식

### 확인 3 — 시크릿 모드

확장 프로그램이 시크릿 창에서 꺼져 있는 경우가 있다.
**시크릿에서 되면 확장 프로그램이 범인이다.**

> 다른 브라우저를 깔아 보는 건 의미가 적다. 크롬북은 사실상 크롬만 쓰고,
> 네트워크 차단이면 브라우저를 바꿔도 똑같이 막힌다.

### 기기 쪽으로 판명되면 — 관리콘솔에서 볼 곳

**기기 → Chrome → 설정 → 사용자 및 브라우저 설정**
왼쪽에서 **조직 단위를 학생 것으로 바꾸고** `URL 차단` 항목을 본다.
`허용할 URL` 칸에 아래 넷을 넣는다. Chrome 은 허용 목록을 차단 목록보다 우선한다.

```
sikke12632.github.io
identitytoolkit.googleapis.com
securetoken.googleapis.com
math-game-e3402-default-rtdb.asia-southeast1.firebasedatabase.app
```

**기기 → Chrome → 앱 및 확장 프로그램** 에서 웹키퍼 확장이 강제 설치돼 있는지 본다.
있으면 **허용 설정은 구글이 아니라 웹키퍼 포털에서** 해야 한다. 그건 정보부 계정이다.

**주의 두 가지**
- 교사 권한이면 **보기만 되고 수정이 안 될 수 있다.** 디벗은 보통 교육청이 상위에서
  관리하고 학교에는 제한된 역할만 준다. 수정 버튼이 회색이면 그게 이유다
- **필터를 통째로 끄지 말 것.** 필요한 건 주소 네 개를 허용 목록에 넣는 것뿐이다.
  필터 자체를 손대면 교육청 정책 문제가 되고, 나중에 원상복구될 때 원인을 못 찾는다

## 보내기 전에 할 일

차단된 디벗에서 **https://sikke12632.github.io/ogu-math/#/check** 를 연다.

- 끝까지 확인이 돌아간 뒤 화면 아래 **&lt;정보부에 보낼 내용&gt;** 상자가 나온다
- **복사하기** 를 누르면 실제로 막힌 주소만 정확히 담긴 글이 복사된다
- 그걸 아래 요청문 뒤에 붙여서 보내면 된다

기기마다 막히는 게 다르므로 **두세 대에서 확인해 보는 게 좋다.**
한 대만 보고 요청하면 허용받은 뒤에 또 다른 게 막혀서 요청을 반복하게 된다.

## 허용이 안 되거나 오래 걸리면

**지금 당장 되는 것 — 혼자 풀기**

https://sikke12632.github.io/ogu-math/#/practice

이 화면은 **Firebase를 전혀 쓰지 않는다.** 문제를 기기 안에서 직접 만들어 낸다.
디벗이 github.io 만 열리면 **차단과 상관없이 지금 바로 쓸 수 있다.**
혼자 풀고 채점받고 오답까지 확인된다. 다만 **팀·게임·교사 화면은 안 된다.**

**인쇄해서 쓰기**

`npm.cmd run dump` 로 100문항을 뽑아 학습지로 인쇄할 수 있다.

**교사 노트북으로 우회 (검증 안 됨)**

앱 화면 자체는 교사 노트북에서 띄워 줄 수 있다.
하지만 **Firebase는 인터넷을 거치므로, Firebase가 막혀 있으면 우회가 안 된다.**
세션·게임까지 되게 하려면 Firebase를 대신할 서버를 노트북에서 돌려야 하고,
그건 코드를 꽤 고쳐야 하는 일이다.

그 전에 **2분짜리 확인**이 먼저다. 디벗이 교사 노트북에 닿기는 하는지 봐야 한다.

1. 교사 노트북에서 `npm.cmd run dev -- --host`
2. 화면에 뜨는 `Network:` 주소를 적는다 (예: `http://172.30.1.45:5173`)
3. 윈도우 방화벽 허용 창이 뜨면 **허용**
4. 학생 디벗 크롬 주소창에 그 주소를 그대로 입력

**열리면** 노트북 서버 방식이 가능성 있다.
**안 열리면** 학교 와이파이가 기기끼리 못 보게 막아 둔 것이라(단말 격리),
노트북 방식은 포기하고 웹키퍼 허용을 받는 수밖에 없다.
