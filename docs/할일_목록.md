# 할 일 목록

순서대로. **각 단계가 끝나야 다음으로 넘어간다.** 앞 단계를 건너뛰면 뒤에서 원인을 못 찾는다.

---

## STEP 0 — 결정하기 (혼자, 5분)

코드를 시작하기 전에 정해야 할 것. 안 정하면 클로드 코드가 임의로 정하고, 나중에 갈아엎는 비용이 크다.

- [ ] **애들이 쓸 기기** — 태블릿 / 크롬북 / 개인 스마트폰
  → 세로 화면 지원 여부가 UI 전체를 바꾼다
- [ ] **카메라 있나** — 없으면 QR이 아니라 6자리 코드 입력이 주 경로
- [ ] **명단 방식** — 학기 초 1회 등록 후 재사용 / 세션마다 입력
- [ ] **전자칠판 띄우는 법** — 교사 PC 미러링 / 전자칠판 자체 브라우저
- [ ] **게임 이름** — 카지노 기표를 피했으니 명칭도 중립적으로

---

## STEP 1 — 준비하기 (혼자, 20분)

클로드 코드가 못 하는 일. 콘솔 조작은 사람만 할 수 있다.

- [ ] Firebase 프로젝트 생성
- [ ] Realtime Database 켜기 (asia-southeast1)
- [ ] Authentication → 익명 로그인 켜기
- [ ] 웹 앱 등록 → `firebaseConfig` 복사해 두기
- [ ] 빈 GitHub 리포 생성
- [ ] 리포에 `docs/` 만들고 설계 문서 2개 넣기
- [ ] 리포 루트에 `CLAUDE.md` 배치 (기존에 쓰던 것 재사용)

---

## STEP 2 — 뼈대 (클로드 코드 세션 1)

**시키는 것**: Vite + React + TS 세팅, 폴더 구조, 타입 정의. 로직은 거의 없다.

- [ ] `src/units/_types.ts` — `Problem`, `SetConfig`, **`Visual` 판별 유니온** (numberline/fraction/figure/table — 1단원은 numberline만 구현, 나머지는 타입만 선언)
- [ ] 단원 모듈에 `mode: 'generated' | 'banked'` 필드 포함 (3·5단원 도형 대비)
- [ ] `src/games/_types.ts` — 게임 모듈 계약
- [ ] `src/units/index.ts`, `src/games/index.ts` — 레지스트리
- [ ] 폴더 스켈레톤 (`session/`, `screens/`, `lib/`)
- [ ] Firebase 초기화 모듈

**끝났는지 판단**: `npm run dev`가 뜨고 빈 화면이 나온다. 타입 파일을 열어 읽고 이해가 되면 통과.

> 여기서 타입이 확정돼야 뒤가 안 흔들린다. 코드가 없어 보여도 이 세션이 제일 중요하다.

---

## STEP 3 — 문제 생성기 (클로드 코드 세션 2)

**시키는 것**: 템플릿 T1~T7 + 가드 G1~G8 + 검증 3종. Firebase는 건드리지 않는다.

- [ ] 가드 공통 모듈 `_guards.ts`
- [ ] T1~T7 구현 (파라미터 포함) — T3 `extra`, T6 `post` 포함
- [ ] **표(table) visual 렌더러** — 1단원에도 표 문항이 많다 (보고서 1.7 발견 6)
- [ ] 독립 검산 (정답을 두 방법으로 계산해 대조)
- [ ] 자동 검사 스크립트 (템플릿당 1000회 생성 → 가드 위반·정답 유일성·보기 중복·NaN 검사)
- [ ] 검수용 덤프 스크립트 (파라미터 조합을 고루 덮는 100문항을 표로 출력)

**끝났는지 판단**: 자동 검사가 전부 통과 + **아래 STEP 4를 통과**.

---

## STEP 4 — 눈으로 검수 (혼자, 20분) ★

**이 단계를 건너뛰면 안 된다.** 자동 검사는 "형식이 맞나"는 보지만 "문제가 말이 되나"는 못 본다.

- [ ] 덤프 100문항 출력해서 훑기
- [ ] 문장이 어색하거나 두 가지로 읽히는 것 표시
- [ ] 5학년 수준에 안 맞는 수치 표시
- [ ] 정답이 애매한 것 표시
- [ ] 수정 요청 → 재생성 → 다시 확인
- [ ] 통과한 결과를 **골든 스냅샷**으로 저장 (이후 회귀 검사 기준)

> 여기까지만 해도 **인쇄해서 학습지로 쓸 수 있다.** 앱이 안 나와도 손해가 아니다.

---

## STEP 5 — 학생 뷰 단독 (클로드 코드 세션 3)

**시키는 것**: Firebase 없이, 혼자 풀고 채점받는 화면.

- [ ] 문항 카드 UI (선택형·단답형·수직선 렌더링)
- [ ] 진행바, 이전/다음 이동
- [ ] 타이머 + 자동 마감
- [ ] 채점 + 결과 화면
- [ ] 오답 확인 화면 (해설 표시)

**끝났는지 판단**: 네 폰으로 열어서 처음부터 끝까지 풀어본다. 수직선이 깨지지 않는지 특히 확인.

---

## STEP 6 — 세션 3화면 (클로드 코드 세션 4)

**시키는 것**: Firebase 붙이고 교사 콘솔 / 보드 뷰 / 학생 뷰. **게임은 아직 없다.**

- [ ] phase 머신 (`lobby → quiz → grading → result`)
- [ ] 교사 콘솔 — 세션 생성, 접속·제출 현황, 수동 제어 버튼
- [ ] 보드 뷰 — QR, 대기 연출, 타이머, 제출 인원
- [ ] 학생 뷰 — 코드 진입, 이름 선택, 풀이, 결과
- [ ] 답안 저장 (디바운스 + localStorage 미러 + 재접속 복구)

**끝났는지 판단**: 기기 3대로 동시에 열어서 한 바퀴 돌려본다.

---

## STEP 7 — 교실 실전 투입 ★

**게임 없이 여기까지로 한 번 수업에 써본다.** 이게 분기점이다.

- [ ] 실제 수업에서 1회 운영
- [ ] 깨진 것 기록: 접속 실패, 화면 깨짐, 타이머 문제, 오작동
- [ ] 걸린 시간 기록 (접속에 몇 분? 풀이에 몇 분?)
- [ ] 애들 반응 기록

> 게임을 먼저 만들면 게임 버그와 인프라 버그가 섞여 원인을 못 찾는다. 여기서 인프라를 먼저 굳힌다.

## STEP 10 — 확장

**순서가 중요하다. 단원 번호순이 아니라 랜덤화 적합도순으로 붙인다.** (아키텍처 설계서 9.1)

- [ ] **4단원 소수의 곱셈** ← 그림이 없어 제일 쉽다. 여기서 코어 코드를 안 고치고 붙으면 구조가 옳은 것
- [ ] 2단원 분수의 곱셈 (분수 렌더러 추가)
- [ ] 6단원 평균과 가능성 (표 생성 + 새 가드)
- [ ] 3·5단원 — 도형이라 `banked` 방식으로 별도 접근
- [ ] 게임 `grouping` 일반화 (duel / freeforall / teamwise / coop)
- [ ] 협력형 게임 1종 — 대전 자체가 부담인 학생용

> **단원을 늘리기 전에 기존 단원을 실제 수업에서 2~3회 굴려 본다.** 안 쓰는 단원 여섯 개보다 잘 도는 단원 두 개가 낫다.

## 세션 운영 규칙

- **클로드 코드 세션은 단계마다 새로 시작한다.** 컨텍스트가 길어지면 뒤로 갈수록 품질이 떨어진다
- 매 세션 첫 지시는 이 형태로: *"설계 근거는 `docs/` 참조. 이번 세션은 STEP N만 한다. 그 외는 손대지 마."*
- 세션 끝에 **무엇을 임의로 정했는지** 보고받는다 (기존 `CLAUDE.md` 규칙)
- ★ 표시된 STEP 4와 STEP 7은 **사람이 직접** 해야 한다. 위임 불가
